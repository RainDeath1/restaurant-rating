# Restaurant Rating API

REST API приложение для управления ресторанами, городами и отзывами посетителей.

Проект разработан в рамках практического задания компании **ASTON**.

Система позволяет управлять ресторанами, получать список заведений определённого города с сортировкой по рейтингу, добавлять отзывы и автоматически пересчитывать средний рейтинг ресторанов.

## Функциональность

- Создание, получение, изменение и удаление городов.
- Создание, получение, изменение и удаление ресторанов.
- Привязка ресторанов к определённым городам.
- Добавление, изменение, получение и удаление отзывов.
- Автоматический пересчёт среднего рейтинга при изменении отзывов.
- Поиск ресторанов по городу с сортировкой по убыванию рейтинга.
- Валидация входящих данных.
- Централизованная обработка исключений с HTTP-статусами.
- Юнит- и интеграционные тесты.

## Архитектура проекта

Приложение использует многослойную архитектуру:

- **Controller** — принимает и обрабатывает HTTP-запросы.
- **Service** — реализует бизнес-логику приложения.
- **Repository** — отвечает за взаимодействие с базой данных.
- **Entity** — описывает сущности базы данных.
- **DTO** — используется для передачи данных через REST API.
- **Exception** — обрабатывает исключительные ситуации.

Для CRUD-операций применяется Spring Data JPA.

Для поиска ресторанов по городу с сортировкой по рейтингу используется Spring JDBC и JdbcTemplate.

## Модель данных

В приложении используются три основные сущности.

**City**
- id — идентификатор города.
- name — уникальное название города.

**Restaurant**
- id — идентификатор ресторана.
- name — название.
- city — привязка к городу.
- averageRating — средний рейтинг.
- votes — список отзывов.

**Vote**
- id — идентификатор отзыва.
- rating — оценка от 0 до 5.
- comment — текст комментария.
- restaurant — ресторан, к которому относится отзыв.

Связи между сущностями:

- Один город может содержать множество ресторанов.
- Один ресторан может содержать множество отзывов.
- Каждый отзыв относится к одному ресторану.

## REST API

### Города

| Метод | Эндпоинт | Описание |
|---|---|---|
| GET | `/api/cities` | Получить все города |
| GET | `/api/cities/{id}` | Получить город по ID |
| POST | `/api/cities` | Создать город |
| PUT | `/api/cities/{id}` | Обновить город |
| DELETE | `/api/cities/{id}` | Удалить город |

Пример создания города:

POST `/api/cities`

```json
{
  "name": "Moscow"
}
```

### Рестораны

| Метод | Эндпоинт | Описание |
|---|---|---|
| GET | `/api/restaurants` | Получить все рестораны |
| GET | `/api/restaurants/{id}` | Получить ресторан по ID |
| POST | `/api/restaurants` | Создать ресторан |
| PUT | `/api/restaurants/{id}` | Обновить ресторан |
| DELETE | `/api/restaurants/{id}` | Удалить ресторан |
| GET | `/api/restaurants/city/{cityId}` | Поиск по городу с сортировкой по рейтингу |

Пример создания ресторана:

POST `/api/restaurants`

```json
{
  "name": "KFC",
  "cityId": 1
}
```

Пример ответа:

```json
{
  "id": 1,
  "name": "KFC",
  "cityId": 1,
  "cityName": "Moscow",
  "averageRating": 0.0
}
```

### Отзывы

| Метод | Эндпоинт | Описание |
|---|---|---|
| GET | `/api/votes` | Получить все отзывы |
| GET | `/api/votes/{id}` | Получить отзыв по ID |
| GET | `/api/restaurants/{restaurantId}/votes` | Получить отзывы ресторана |
| POST | `/api/restaurants/{restaurantId}/votes` | Добавить отзыв |
| PUT | `/api/votes/{id}` | Изменить отзыв |
| DELETE | `/api/votes/{id}` | Удалить отзыв |

Пример добавления отзыва:

POST `/api/restaurants/1/votes`

```json
{
  "rating": 5,
  "comment": "Excellent food!"
}
```

Пример ответа:

```json
{
  "id": 1,
  "rating": 5,
  "comment": "Excellent food!",
  "restaurantId": 1
}
```

## Автоматический пересчёт рейтинга

После добавления, изменения или удаления отзыва приложение автоматически пересчитывает средний рейтинг ресторана.

Рейтинг определяется как среднее арифметическое всех оценок.

Например, при оценках 5, 4 и 3:

**(5 + 4 + 3) / 3 = 4.0**

Если у ресторана отсутствуют отзывы, рейтинг равен 0.0.

Пересчёт выполняется в сервисном слое с использованием транзакций Spring и агрегирующего запроса AVG() через JPA.

## Поиск и сортировка

Для получения ресторанов конкретного города используется эндпоинт:

GET `/api/restaurants/city/1`

Поиск реализован через Spring JDBC с использованием JdbcTemplate.

Результаты сортируются по среднему рейтингу от большего к меньшему. Для ресторанов с одинаковым рейтингом используется дополнительная сортировка по ID.

## Запуск приложения

### Требования

- JDK 21
- Git (для клонирования репозитория)

Отдельная установка Gradle не требуется, поскольку проект содержит Gradle Wrapper.

### Сборка

В Windows PowerShell:

```powershell
.\gradlew.bat clean build
```

В Linux/macOS:

```bash
./gradlew clean build
```

### Запуск через Gradle

Windows:

```powershell
.\gradlew.bat bootRun
```

Linux/macOS:

```bash
./gradlew bootRun
```

### Запуск через JAR

После сборки можно запустить приложение:

```bash
java -jar build/libs/restaurant-rating-0.0.1-SNAPSHOT.jar
```

После успешного запуска REST API доступен на порту 8080.

Базовый адрес:

`http://localhost:8080`

## База данных H2

Используется H2 Database в режиме in-memory.

Параметры подключения:

| Параметр | Значение |
|---|---|
| JDBC URL | `jdbc:h2:mem:restaurantdb` |
| Username | `sa` |
| Password | пустой |

H2 Console:

`http://localhost:8080/h2-console`

Для просмотра таблиц можно выполнить:

```sql
SELECT * FROM CITIES;
SELECT * FROM RESTAURANTS;
SELECT * FROM VOTES;    
```

**Важно:** поскольку база работает в оперативной памяти, данные не сохраняются после завершения приложения.

## Обработка ошибок

В приложении используется централизованный обработчик исключений `GlobalExceptionHandler`.

Поддерживаются следующие основные HTTP-статусы:

| HTTP-код | Описание |
|---|---|
| 200 OK | Запрос успешно выполнен |
| 201 Created | Ресурс создан |
| 204 No Content | Ресурс удалён |
| 400 Bad Request | Некорректные входящие данные |
| 404 Not Found | Ресурс не найден |
| 409 Conflict | Нарушение ограничений базы данных |

Ошибки возвращаются клиенту в формате JSON с указанием статуса, времени, сообщения и адреса запроса.

## Тестирование

Для тестирования используются JUnit 5 и Mockito.

Реализованы следующие тестовые классы:

- `CityServiceTest` — проверка работы с городами.
- `RestaurantServiceTest` — проверка бизнес-логики ресторанов.
- `VoteServiceTest` — проверка операций с отзывами и пересчёта рейтинга.
- `RestaurantJdbcRepositoryTest` — интеграционная проверка поиска и сортировки через Spring JDBC и H2.

Запуск всех тестов в Windows:

```powershell
.\gradlew.bat test
```

В Linux/macOS:

```bash
./gradlew test
```

Отчёт о тестировании создаётся по пути:

`build/reports/tests/test/index.html`
